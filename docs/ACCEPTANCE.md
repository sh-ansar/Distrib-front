# Предварительная приёмка — Distrib-front

## Автоматические тесты

`npm run typecheck` → TypeScript.
`npm test` → Vitest: суммы, просрочки, остатки по консигнации, переходы, резервы, запрет двойного назначения.
`npm run build` → production-сборка Vue.

GitHub Actions `frontend-checks.yml` только проверяет, **ничего не публикует**.

## Ручной smoke-набор (демо)

1. Главная: все KPI помечены как демо, нет заявлений о подключении 1С.
2. Магазины: поиск, фильтры, создание контрагента с валидным вымышленным БИН, добавление точки, переход в карточку, редактирование и заметки.
3. Визиты: запланировать, начать, завершить, пропустить с причиной; нельзя дублировать активный визит на одну дату или изменять чужие магазины.
4. Заявки: создать заказ, добавить позиции, проверить сумму, подтвердить, собрать, перевести в «Готова». Нельзя подтвердить заблокированного клиента, превысить лимит с учётом других открытых заявок, подменить цену или оформить заказ без остатков.
4. Рейсы: выбрать готовый заказ соответствующей даты, машину, водителя. Проверить переполнение веса, повторное назначение, смену статусов, доставку, завершение, печать.
5. Дебиторка: просроченные и текущие долги, фильтр, отметка вымышленной оплаты бухгалтером; никакого изменения 1С.
6. Консигнация: сверить проданный/возвращённый товар, отклонить попытку указать больше оставшегося количества.
7. Документы: реестр работает, но UI **не обещает загрузку** файлов; создание только метаданных.
8. Роли: выбрать торгового представителя, водителя, бухгалтера — должны быть скрыты нерелевантные разделы. Это не серверная защита.
9. Сброс демо: подтверждение удаления в настройках, повторная загрузка из синтетических данных.
10. Адаптивность: 1440px, 1024px, 768px, 390px, 320px. Мобильный сайдбар, прокрутка таблиц, формы, печать маршрутного листа.
11. API-режим: при `VITE_DATA_MODE=api` не должно возникать ложных успешных действий или отображаться демоданные.
12. Отказ от загрузки: реальные фото, PDF, документы не записываются в localStorage.

## Блокирующие до промышленной эксплуатации

- Серверная авторизация и объектные разрешения.
- Проверенные endpoints с доменной валидацией, транзакциями и аудитом.
- Интеграция с учётной 1С и фактическими планшетными заявками.
- Реальный файловый API, отдельное закрытое хранилище, жизненный цикл накладных.
- Функциональные и интеграционные проверки, ошибки сети, конфликтные записи, пилот с реальными операторами.
- Финансовая приёмка и юридически корректный учёт консигнации.
- Проверка различий браузеров и реальной доступности сборки по согласованному URL.

**До этой приёмки это только интерактивный frontend-прототип.**

## Darmen New Wave · расширенное досье и рейсы

- Администратор и супервайзер редактируют досье компании; остальные роли только просматривают.
- Вводится торговое название, БИН, директор, контакт, договор, условия поставки и окно приёмки.
- Изменения не перезаписывают кредитный лимит и бухгалтерскую задолженность.
- Старая демонстрационная база v1–v3 открывается с новой схемой v4 без потери созданных записей.
- Торговый представитель видит только рейсы по своим закреплённым магазинам.
- В маршруте видны юридическое лицо, магазин, контакт, окно приёмки, следующая точка и дата последней отметки.
- Отсутствие GPS и точного ETA явно обозначено. Демонстрационные отметки доставки не выдаются за телематику.

## Партии, магазины, автопарк и накладные

- Приход партии создаёт запись с номером, датой прихода и окончания годности, исходным количеством, остатком, источником и сотрудником; складской остаток увеличивается.
- Партия с истёкшим сроком не участвует в доступном к отгрузке остатке. Полная доставка проводится по FEFO (ближайший действующий срок), либо вся доставка отклоняется.
- Отгрузка на торговую точку создаёт журнал партий, но не выдаётся за фактический остаток на полке. Представитель отдельно фиксирует пересчёт.
- План торгового представителя включает выручку, визиты и уникальные магазины; менять план могут уполномоченные роли.
- Диспетчер назначает грузовик, водителя и экспедитора; нельзя дважды занять машину или сотрудника на одну дату. Масса и объём сверяются с лимитами автомобиля.
- Накладная выбирается на мобильном устройстве, изображение видимо только в локальном предпросмотре. «Распознавание» генерирует образец полей из тестового заказа, не читает документ. Оригинал не сохраняется.
- Проверить 320 / 375 / 390 / 428 / 768 px, модалки, длинные строки, отсутствие горизонтальной прокрутки, читаемость синей темы.
