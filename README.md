# ITP Distribution — Distrib-front

Frontend-платформа управления дистрибуцией: торговые точки, юридические контрагенты, заявки, задолженность, товар под реализацию, склад, рейсы, накладные и действия сотрудников.

> **Статус: интерактивный frontend-прототип.** Все демонстрационные лица, компании, адреса, суммы, номера машин и БИН вымышлены. Интеграции с 1С, реальной системой торговых представителей, аутентификация и загрузка файлов пока **не подключены**. Нельзя использовать эту сборку для учёта или реальных поставок.

## Возможности интерфейса

- **Обзор:** KPI, активные заявки, просроченные долги, доставки, последние события.
- **Торговые точки:** реестр, поиск, фильтр районов, карточка магазина, документы, примечания, история; разделение точки и юридического контрагента.
- **Заявки:** создание, проверка остатков и лимита клиента, статусы, резерв на основном складе, стоимость по позициям.
- **Дебиторка:** документы расчётов, сроки, остатки, просрочки, ручная приостановка отгрузок, демо-оплаты.
- **Под реализацию:** отдельный реестр переданного товара, сверка продаж и возвратов, расчёт остатка.
- **Склады:** остатки по двум синтетическим складам, резерв, доступное количество, категории товаров.
- **Маршруты:** назначение готовых заказов по дате, машинам, водителям, контроль грузоподъёмности; маршрутный лист, статусы доставки, печать.
- **Документы:** реестр метаданных с привязкой к объектам. Файловые байты не сохраняются.
- **Роли:** администратор, директор, супервайзер, торговый представитель, диспетчер, кладовщик, водитель, бухгалтер. Демо-переключение ролей показывает ожидаемый UX.

## Стек

Vue 3 + TypeScript + Vite 7 + Pinia + Vue Router + Lucide icons. Адаптивная оболочка и повторно используемые UI-компоненты в `src/components/ui`. На момент инициализации исходный репозиторий `itpmining/vue_basic_components` не был доступен этому GitHub-подключению: его API и стили нельзя считать проверенными. См. [руководство по миграции компонентов](docs/DESIGN-SYSTEM.md).

## Запуск для разработки (не деплой)

```bash
npm install
cp .env.example .env
npm run dev
```

Команды проверки: `npm run typecheck`, `npm test`, `npm run build`.

Приложение использует `VITE_DATA_MODE=demo` по умолчанию. В демо данные хранятся в `localStorage` текущего браузера с версионированием схемы. Изменения можно сбросить в настройках.

`VITE_DATA_MODE=api` **не включает** готовое API: приложение показывает блокирующий экран, пока backend, серверная аутентификация и источник данных не реализованы. Так мы не показываем тестовые данные под видом боевых.

## Границы безопасности

- Демо-переключатель роли **не авторизует** пользователя и не защищает данные. Серверу нужен строгий RBAC, объектные права (точки своего маршрута/региона) и аудит.
- Никакие API-ключи 1С, пароли, реальные счета, персональные данные или сканы документов не должны попадать в этот публичный репозиторий.
- В демо **не отправляются** заказы, оплаты, документы или движения остатков в 1С.
- Файлы не загружаются. Метаданные без байтов нельзя считать юридическим подтверждением доставки.
- Финансовые суммы демо не являются бухгалтерскими данными.
- Выгрузки, реальная синхронизация и промышленный режим требуют backend и пилотной приёмки.
